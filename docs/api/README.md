# API 명세 제안

화면에서 쓰는 API의 요청·응답 모양을 화면 단위로 제안하는 규칙과 템플릿입니다.

- 위치: **그 화면의 GitHub 이슈 본문** (예: S05 → 이슈 #15). 리뷰·머지 없이 바로 고칠 수 있고, 수정 이력이 남고, 백엔드와 댓글로 합의합니다.
- 제목 줄: `[<ID> - API 명세 제안] <PR 제목>` (예: `[S05 - API 명세 제안] [S05] feat: event detail #15`)
- 화면 PR 본문 맨 위에 `API 명세: #15`처럼 이슈 번호를 적습니다. PR의 `Closes #15`로도 연결됩니다.
- 상태: 초안 → 합의 → 구현 → 연결 완료. 바뀌면 이슈 본문을 고치고 변경 이력에 한 줄 남깁니다.

## 공통 규칙 (제안)

- 주소: 모든 API는 `/api`로 시작 (배포에서는 Vercel rewrites가 백엔드로 전달)
- 로그인: `Authorization: Bearer <JWT>` 헤더
- JSON 필드 이름: camelCase (예: `startDate`)
- 날짜·시간: ISO 8601, 한국 시간 (예: `2026-11-29T10:30:00+09:00`)
- 좌표: `lat`, `lng` 숫자
- 목록: `items` + `page`, `size`, `total`
- 에러: HTTP 상태 코드 + `{ "code": "EVENT_NOT_FOUND", "message": "..." }`
- 일본어 필드: 원문 필드 이름 뒤에 `Ja` (예: `title` / `titleJa`)

````markdown
## 1. 행사 상세 조회

- 요청: `GET /api/events/{eventId}`
- 로그인: 불필요
- 화면에서 쓰는 곳: 상세 상단 제목·기간·장소, 지도 핀

### 요청 값

- path `eventId` (number) — 행사 ID

### 응답 (200)

```json
{
  "id": 123,
  "title": "서울빛초롱축제",
  "titleJa": "ソウル光の提灯祭り",
  "startDate": "2026-11-28T18:00:00+09:00",
  "lat": 37.5696,
  "lng": 126.9784
}
```

### 응답 필드

| 필드      | 타입   | 필수 | 설명                                        |
| --------- | ------ | ---- | ------------------------------------------- |
| `id`      | number | ✅   | 행사 ID                                     |
| `titleJa` | string | —    | 일본어 행사명. 없으면 화면은 `title`을 표시 |

### 에러

| 상태 | code              | 화면 동작                         |
| ---- | ----------------- | --------------------------------- |
| 404  | `EVENT_NOT_FOUND` | 「イベントが見つかりません」 안내 |

## 변경 이력

- 11/27 초안 (○○)
````
